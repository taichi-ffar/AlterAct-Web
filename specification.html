1. 概要

AlterActは、3人のキャラクターで24枚のデッキを構成し、各キャラクターに対応する 4時点のタイムラインへカードを配置して戦う対戦カードゲームである。 本アプリは公式ルールのデジタル実装検証、ダメージ予測の可視化、操作性評価を目的とする。

クライアント

Unity WebGL / Windows x64 / Android ARM64。画面とゲーム処理はC#で実装。

対戦サーバー

Node.js + Express。部屋コード、参加権限、状態バージョン、途中復帰を管理。

公開基盤

Webクライアントと通信APIをRenderで公開。GitHubリポジトリから自動デプロイ。

2. 対象範囲

対象

  • タイトル、対戦モード選択、キャラクター編成、対戦、勝敗表示。
  • NPC、同一端末でのローカル2人対戦、部屋コード式通信対戦。
  • カード配置、Cost、AlterAct、対象指定、トークン、ダメージ予測、ログ。
  • スマートフォンの縦横切替、全画面表示、音量設定。

対象外または未完成

  • アカウント、レーティング、マッチメイク、観戦、チャット。
  • サーバー側での公式ルール完全検証と高度な不正対策。
  • 製品版の演出、音源、課金、分析、運営管理機能。

公式ルールと実装に差異が見つかった場合は公式ルールを優先し、 実装・チェックリスト・本仕様書を同じ変更単位で更新する。

6. ゲーム仕様

編成と初期化

  • 各プレイヤーは異なるキャラクター3人を選択する。
  • 選択順を前衛・中衛・後衛へ割り当てる。
  • 初期編成は初心者おすすめの「前衛サキ・中衛ラプラ・後衛ヘイゼ」。
  • 選択キャラクターのカード各8枚、合計24枚をシャッフルして山札とする。
  • 両プレイヤーは初手を4枚引く。先攻はランダムまたは明示選択できる。

タイムライン

  • 各キャラクターは時刻1～4の4時点を持つ。
  • カードはキャラクター単位で、未配置かつ最も早い時点へ配置する。
  • 攻撃・対象指定効果はカードと同じ時刻の対象時点を参照する。
  • Rangeは前衛・中衛・後衛の縦方向の距離へ適用する。

ターン進行

ターン先攻の必須配置後攻の必須配置
1ターン目1回2回
2～6ターン目2回2回
7ターン目1回0回

必須配置後は任意でAlterActを1回実行でき、手番終了時に最大4枚引く。 後攻の7ターン目終了後、時刻順に効果処理と勝敗判定を行う。

8. キャラクター

キャラクターHP推奨位置固有仕様の概要
ラプラ6前・中最初の自分ターン開始時に1枚引く。
サキ7前自身のカードのRangeが減少しない。
ヘイゼ4後重力弾・電子弾・量子弾を「狙撃」へ乗せる。
アイネ4前・中自身のタイムラインの裏向きカードはBarrier 2。
ステラ5中・後スターを時点へ置き、味方のAttackを強化する。
マクス6中Costカードをカードの下へ裏向きで置ける。
リンゴ5前・後キーワード〈浮遊〉を使用する。
ロア5後キーワード〈バタフライ〉で味方を強化する。
シュロ4前・中ロスト後の時点でも自身のカードが発動する。

シンは実装対象外。カードは9キャラクター×3種の全27種で、各キャラクター8枚。 正式な数値と効果全文はCardCatalog.csを参照する。

9. UI・操作仕様

  • プレイヤー側を画面下、相手側を画面上へ固定する。
  • Attackは橙、Barrierは青、Commonは緑を基本色とする。
  • 配置カードを選ぶと、左側の詳細領域にカード名、Cost、キャラクター、種別、数値、効果を表示する。
  • 攻撃元と対象をノード型リンクで接続し、自分の攻撃は青、相手の攻撃は赤で表示する。
  • 全6時点が埋まった時刻はダメージトレード演出を一度表示する。
  • 画面の縦横変更を実行中に検出し、状態を維持したままUIを再構築する。
  • 手札は横スクロールし、ドロー順・キャラクター・種別・Costで表示ソートできる。

11. 通信対戦

構成

  • クライアントはHTTPSでRender上の対戦APIへ接続する。
  • 6文字の部屋コードとプレイヤー別トークンを使用する。
  • クライアントは約1.25秒間隔で部屋状態をポーリングする。
  • サーバーは手番所有者と期待バージョンを検証し、古い更新を拒否する。
  • 本番環境は東京リージョンのUpstash Redisへ確定済み状態を保存し、Renderサービス再起動後も復帰できる。
  • 部屋は最終アクセスから24時間で期限切れになる。

HTTP API

MethodPath用途
POST/api/rooms部屋を作成し、PLAYER 1トークンを発行する。
POST/api/rooms/:code/join部屋へ参加し、PLAYER 2トークンを発行する。
GET/api/rooms/:code?token=...状態の取得、待機、途中復帰。
PUT/api/rooms/:code/state確定済みゲーム状態をバージョン付きで保存する。
GET/healthサーバーと使用中ストレージのヘルスチェック。

Cost・トークン・対象指定の途中状態は送信しない。切断時は直前の確定操作へ戻る。 現行サーバーは完全な公式ルール判定を行わず、改造クライアント対策は限定的である。

12. 非機能要件

  • 可用性：通信API停止時もNPC・ローカル対戦には影響しない。
  • 復旧性：通信対戦は確定操作単位で途中復帰できる。
  • 操作性：主要操作はマウスとタッチの双方で完結する。
  • 表示：PC横画面とスマートフォン縦横画面へ動的対応する。
  • 文字：Noto Sans CJK JPを同梱し、日本語を高解像度で表示する。
  • 再現性：通信対戦では乱数状態をスナップショットへ含める。
  • 保守性：機能変更時にコード、テスト、チェックリスト、本仕様書を同期更新する。

14. 既知の制約

  • 対戦サーバーは公式ルールを完全検証しない。
  • 通信スナップショットには非公開領域も含まれ、ペイロードレベルの秘匿は未完成。
  • Upstash無料データベースは長期間アクセスがない場合に休止・アーカイブされる可能性がある。
  • マクス「メモリ・リセット」の任意手札選択UIは未実装。
  • Costカードを戻す山札位置を指定する完全な山札操作UIは未実装。
  • BGM・効果音の設定値は保存するが、製品用音源は未追加。
  • 実機2台による通信対戦の全7ターン通し回帰は継続確認項目。
