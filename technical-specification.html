1. 全体像

ゲーム本体は単一のUnityシーンからコード生成UIを構築するPublic Betaです。AlterActPrototypeがローカルゲームの唯一の状態所有者となり、画面表示はその状態から再構築します。通信対戦では同じ状態をJSONスナップショット化し、Nodeサーバーが部屋単位でバージョン管理します。

  ├─ AlterActPrototype        局面状態、入力、UI生成、NPC、シミュレーション
  │    ├─ .Navigation         ホーム、キャラクター図鑑、編成、設定

通信サーバーは「正しいクライアント同士の同期と途中復帰」を担当します。カード効果の完全な不正入力検証は、Public Beta 0.9.0ではUnityクライアント側が担う既知の制約です。

起動と画面遷移

RuntimeInitializeOnLoadMethod→StartPrototype / Awake→ShowTitleScreen（ホーム）→PLAY / DECK / CHARACTER ARCHIVE→対局・編成・参照

UIはUnity Editor上の固定レイアウトに依存せず、CreateCanvas、Panel、Label、Buttonで実行時に生成します。CreateCanvasはScreen Space OverlayのpixelPerfectを有効化し、端数座標による文字のぼけを抑えます。同梱Noto Sans CJK JPはHinted Smoothで描画します。WebGLテンプレートはタッチ端末の描画倍率を最低2・最大4、非タッチ端末を最大2に制限します。Updateで縦横と狭幅横画面の切替を監視し、変化時はRebuildForOrientationChangeで局面状態を維持したまま画面を組み直し、続けてRefreshBoardStateで配置カード・裏向き・対象選択・LOSTの色を復元します。横画面は盤面と下部のプレビュー／手札／操作を分離し、幅1700未満では編成・手札カードを圧縮します。縦画面は実際の縦横比から_portraitBoardExtraを算出し、基準解像度を超える高さを6キャラクター行へ均等配分して盤面と手札の空白を防ぎます。背景グリッドと左端アクセント線は上下ストレッチアンカーで全高を覆ります。RefreshTargetArrowsの最後では、表示中のトークン選択・履歴パネルを再び最前面へ上げ、再生成された矢印やダメージ数字が操作面へ重ならないようにします。

ホームとキャラクター図鑑

ShowTitleScreenはホームの4導線を生成し、ShowPlayModeMenuだけが対戦方式選択をモーダル表示します。ShowCardLibraryは9人のキャラクター一覧、プロフィール、専用カード3種類の領域を構築します。SelectLibraryCharacterが選択中のキャラクター名を保持し、RefreshCharacterLibraryがCardCatalog.Charactersの人物紹介・所属・HP・推奨位置・主なRange・5項目の評価・固有効果と、CardCatalog.Cardsから該当する3種類の能力・効果文・CardData.FlavorTextを再生成します。画面回転時はAppScreen.CardLibraryを判定して図鑑画面を再生成し、_selectedLibraryCharacterを維持します。

チュートリアル

AlterActPrototype.Tutorial.csが基礎4ステージとキャラクター別9ステージの固定教材盤面を構築します。Resources/Tutorial/tutorial_dialogue.jsonには13ステージと75 Cueを収録し、stageId、sceneId、order、表示トリガー、案内テキスト、要求操作、有効対象、ハイライト、成功文、誤操作ヒント、進行制限を保持します。TutorialDatabase、TutorialStageRecord、TutorialCueRecordへJsonUtilityで読み込みます。TutorialFocusRowsとTutorialFocusTimesが対象記述を操作可能な行・時刻へ変換し、非対象領域を減光します。過去CueはTutorialStateCaptionで確認済み・配置済み・対象指定済み・Cost確定・解決済みの盤面表示へ変換されるため、Cue進行後も操作結果を視覚的に追跡できます。

ShowTutorialSelectionが解放状態とクリア状態を表示し、ShowTutorialStageが横画面・縦画面用の教材盤面とN.O.A.案内を生成します。TutorialZoneはCueごとの操作を盤面・手札・ガイドへ割り振り、有効な操作だけをButtonとして生成します。AdvanceTutorialCueで成功文を表示して次へ進み、CompleteTutorialStageでステージ別のPlayerPrefsへ保存します。基礎は順次解放し、B04完了後に9つのキャラクタートライアルを解放します。初版は通常対戦の局面状態・Undo・通信スナップショットと分離したガイドシミュレーションです。

3. 局面状態モデル

盤面キーはすべて (player, character, time) です。playerは0/1、characterは前衛・中衛・後衛の0〜2、timeは時刻1〜4に対応する0〜3です。

フィールド型意味
_hands / _decksプレイヤーごとのList<CardData>手札と山札。支払いカードは選択してから山札に戻し、再シャッフルする。
_placed盤面キー → CardDataその時点に見えている最上層カード。裏向きならFaceDownを持つ。
_stacks盤面キー → List<StackLayer>実データの積層。カード、裏向き、Costかどうかを保持し、マクス等の下置きを表現する。
_targets攻撃元キー → 対象キー攻撃・対象指定効果の対象。同一時刻の相手キャラだけを選択させる。
_stars / _specialAmmo盤面キー → 値ステラのスター枚数、ヘイゼの特殊弾。AlterAct時は取り付け済み特殊弾を未使用へ戻す。
_hp / _bonusHp2×3の整数配列開始HPと、デモン・チャージ等で得た恒久補正。
_randomGameRandomxorshift系の決定的乱数。内部Stateも通信スナップショットに含める。

Undoの境界

TurnActionSnapshotは手札・山札・盤面・積層・対象・トークン・HP・ログ・手番進行を深く複製します。CommitPlacementの直前にSaveUndoSnapshotを呼び、同一手番内の確定操作だけをUndoLastTurnActionで戻します。通信中は確定後に送信されるため、復帰対象は「途中の選択」ではなく「最後に確定した局面」です。

4. 手番・配置・Costの論理

カード選択→配置マス選択→通常Cost選択→AlterCost選択（必要時）→対象 / トークン選択→確定・同期

PaymentStageは None、NormalCost、AlterActCost の3段階です。通常CostとAlterAct Costは別々に選択され、支払いカードをランダムに決めません。

SlotClickedは、手札カード選択中に自分の配置済み時点をクリックした場合だけPlaceCardへ渡してAlterActを開始します。カード未選択時の配置済み時点クリックはShowBoardCardDetailへ渡し、参照操作として扱います。

7ターンの手番順

ScheduledAdvancesは先攻を1・2・2・2・2・2・1回、後攻を2・2・2・2・2・2・0回とし、双方の合計を12回にします。EndTurnは固定のPLAYER番号ではなく_firstPlayerから後攻を算出し、同じラウンドを先攻→後攻の順に処理します。RequiredAdvancesは通常この予定値を返しますが、0.9.0以前のB先攻保存データだけは後攻Aの未配置数を返して不足分を補完します。後攻の7ターン目終了時はAllTimelinesFilledで全24時点を検査し、未配置があればFinalizeBattleを呼びません。

CommitPlacementの処理順

  1. Undo用スナップショットを保存する。
  2. PayAndRemovePlayedCardでプレイカードと選択済みCostを手札から外す。通常Costは山札へ戻して再シャッフルする。マクスの選択時だけ、そのCostを同じマスのスタック下へ裏向きで保存できる。
  3. AlterActならReturnMountedTokensForAlterActでヘイゼの特殊弾を未使用状態へ戻す。
  4. Cost層、プレイカード層の順に_stacksへ積み、見えるカードを_placedへ保存する。
  5. ResolvePlacementEffectsで即時配置効果を処理する。メモリ・リセットはQueueTokenSelectionから任意使用を提示し、BeginMemoryResetHandSelectionで手札領域選択、PlaceHandCardUnderMemoryResetで下置きとドローを確定する。NPCはResolveAutomaticMemoryResetで同じ順序を自動処理する。
  6. 攻撃カードなら対象指定、必要ならトークン選択を開始する。終了後に盤面・手札・予測・操作ログを更新し、通信中は状態をpublishする。
裏向きカードは原則「効果なし」です。ただしアイネ編成ではGetEffectiveStatsが裏向きカードにBarrier 2を与えます。配置時に実行済みの効果は、裏向き化しても遡って取り消しません。

5. ダメージ予測・解決アルゴリズム

Simulateは現在の盤面から時刻1〜4を順番に解決する予測処理です。実際の手札や盤面を破壊せず、Simulationへ時刻ごとの攻撃ログ、被ダメージ、残HPを作ります。

for time = 0..3:
  alive と HP を前時刻の結果から引き継ぐ
  ResolveTime(time) を実行
  燕返しでこの時刻の被ダメージが発生したなら最大4回まで再解決
  直接ダメージ + max(0, 通常ダメージ - Barrier) をHPへ反映
  HP 0以下のキャラクターをLOSTにする

ResolveTimeの順序

  1. その時刻で行動できるカードから有効ステータスを算出し、Barrierを対象キャラクター単位で合計する。
  2. 混沌の領域・飛躍する果実など、個別の即時ダメージを通常ダメージへ加算する。
  3. 攻撃カードは対象の有無、対象の生存、Range、見切りブロックを順に検証する。通れば通常または軽減不能ダメージへ加える。
  4. シュロの「すいっちおん！」が過去の時刻から持ち越す遅延ダメージを加える。
  5. direct + max(0, normal - barrier) を計算し、浮遊中で合計6以上なら0に置換する。

Range距離

CoordinateはプレイヤーAを前→後で2,1,0、プレイヤーBを前→後で3,4,5へ並べます。Distanceはこの両端の間にいる生存キャラクター数を数えるため、LOSTが発生すると同じ前後配置でも射程距離が変わります。これが「Rangeは縦方向に影響する」実装です。

有効ステータス

GetEffectiveStatsが基礎Attack / Barrier / Rangeへ、スター、特殊弾、バタフライ、浮遊連携、下の裏向きカード数、対象指定妨害などを合成します。

盤面表示

IsProjectedLostBeforeTimeは直前の時刻のHpAfterだけを参照します。同時刻の全カードはLOST確定前に発動するため、予測LOSTは次の時刻からBoardStateSuffixが`!`だけを表示し、BoardStateDetailが理由を詳細欄へ表示します。終了時はLOSTと暗赤色へ統一します。独立した中央予測帯は作らず、RefreshTargetArrowsが接続線を盤面レイヤー、合計ダメージ数字を入力透過のTarget Damage Labels前景レイヤーへ分離して描画します。

6. 通信対戦と途中復帰

POST /rooms
部屋作成→POST /join
2人目参加→ホストが初期局面を保存→約1.25秒ごとにGET→確定操作だけPUT

OnlineGameStateは手札・山札をカードID配列で、盤面・スタック・対象・トークンをキー値配列で保存します。乱数状態、HP、ログ、時刻演出済みフラグも含むため、再読込後に同じ山札順と盤面へ戻れます。

PLAYER B視点の反転

クライアント内部では常に「自分」をローカルplayer 0、「相手」をローカルplayer 1としてUIを描きます。通信データは部屋の正規順序で保存するため、CanonicalPlayerとLocalPlayerがPLAYER Bでは0/1を反転します。これにより参加側も自分のチームが常に画面下に表示されます。

競合防止

保存要求にはexpectedVersionを含めます。サーバーの最新versionと一致しなければ409 VERSION_CONFLICTを返し、クライアントはサーバー状態を復元します。また、初期化以外の保存は現在の手番プレイヤーだけが実行できます。

部屋コードと参加者トークンを端末のPlayerPrefsへ保存します。IPアドレスは復帰の識別子に使いません。トークンを失った端末からは、同じ部屋でも復帰できません。

8. 実装上の不変条件と変更時の注意

  • 通信スナップショットで使うカードIDはCardCatalog.Cardsの配列インデックスです。カード一覧の並び順を変える場合は、保存済み対戦との互換性を検討します。
  • _placedだけを上書きしてはなりません。Costや下置きカードを含む実データは_stacksにも積みます。マクスの裏向き枚数参照に必要です。
  • 新しい確定操作を追加する場合は、TurnActionSnapshot、CaptureOnlineGameState、RestoreOnlineGameStateの3箇所へ状態を追加します。
  • 新しいカード効果を追加する場合は、配置時ならResolvePlacementEffects、時刻解決ならResolveTimeまたはGetEffectiveStats、盤面表示ならBoardStateSuffix等を更新します。
  • 通信APIの状態スキーマを破壊的に変える場合はOnlineGameState.schemaを上げ、旧スキーマの扱いを決めます。
  • Upstash無料DBは長期間アクセスがない場合に休止・アーカイブされる可能性があります。部屋自体は最終アクセスから24時間で意図的に失効します。

確認手順

  1. サーバー: node --testでAPI・競合・ヘルスのテストを実行する。
  2. Unity: PlayModeスモークでタイトル、編成、配置、Cost、AlterAct、トークン、Undo、結果を確認する。
  3. 通信: 2ブラウザで作成→参加→確定→再読込→復帰を確認する。
  4. 本番: /healthのstorageがredisであることを確認する。
